# pager-lang v1.0.0 — stable

**1.0.** The public API is frozen and stable. v0.1.0 stood up the scaffold and the quality gates; v0.2.0 built the core — page-aligned regions backed by `mmap` and `VirtualAlloc`, on-demand protection changes, guard pages, and the safe accessors that enforce write-xor-execute. This release ratifies that surface as the `1.0` contract: it follows Semantic Versioning, carries no breaking changes before `2.0`, and ships with the full test and benchmark suite verified on Linux and Windows, including the x86-64 tests that assemble and execute real machine code on each.

There is no breaking change from `0.2.0` — a `0.2.0` program compiles and behaves identically. This release adds only the stability documentation.

## What is pager-lang?

The memory foundation a JIT needs. A just-in-time compiler emits machine code at run time and then jumps into it, which requires memory the operating system will let the CPU *execute* — something ordinary heap allocations are not. pager-lang hands out that memory: page-aligned regions whose access permissions can be changed independently of the rest of the address space, with optional guard pages, and nothing more. Regions are backed by `mmap` on Unix and `VirtualAlloc` on Windows through direct FFI, with no third-party dependencies on the core path.

```rust
use pager_lang::{Protection, Region};

let mut region = Region::new(4096).expect("map a page");
region.write(0, &[0x90, 0x90, 0xC3]).expect("write while writable");
region.protect(Protection::ReadExecute).expect("flip to executable");
assert!(region.as_mut_slice().is_none()); // no longer writable
```

## The 1.0 surface

The frozen contract is three types and one function:

- **`Region`** — an owned, page-aligned mapping that frees itself on drop. Created read/write with `new` or `with_guard_pages`; `write`, `protect`, the protection-gated `as_slice` / `as_mut_slice`, the raw `as_ptr` / `as_mut_ptr`, and the `len` / `protection` / `has_guard_pages` accessors. `Send`, `Sync`, `Debug`.
- **`Protection`** — the access a region permits (`None`, `Read`, `ReadWrite`, `ReadExecute`, `ReadWriteExecute`) with `is_readable` / `is_writable` / `is_executable`.
- **`PagerError`** — the failure type, carrying the OS error code (`errno` / `GetLastError`) for OS-level variants. `Display`, `Error`, and `#[non_exhaustive]`.
- **`page_size`** — the host page size, queried once and cached.

`PagerError` is `#[non_exhaustive]`, so a future failure mode is a non-breaking addition. `serde` derives for `Protection` and `PagerError` ship under the `serde` feature.

## SemVer promise

The crate follows [Semantic Versioning](https://semver.org):

- No documented item is removed or changed in a breaking way within `1.x`; breaking changes wait for `2.0`.
- New functionality is additive and arrives in minor releases. A new `PagerError` variant is a minor change.
- The MSRV is Rust `1.85`; raising it is a minor change, never a patch.
- Behaviour is part of the contract: a region maps, protects, and frees the same way, and the safe accessors gate on protection exactly as documented.

The full statement lives in [`docs/API.md`](https://github.com/jamesgober/pager-lang/blob/main/docs/API.md#semver-promise).

## Breaking changes

**None.** `1.0.0` makes no breaking change to the `0.2.0` surface.

## Safety

The crate uses `unsafe` where it must — FFI to the OS memory calls and the raw-pointer work behind the safe accessors. Every `unsafe` block carries a `// SAFETY:` justification, every `unsafe fn` documents its invariants, and the operations are covered by tests that map, write, protect, free, and execute real code on both Linux and Windows under `#![deny(unsafe_op_in_unsafe_fn)]` and `#![deny(clippy::undocumented_unsafe_blocks)]`. The safe surface is designed so no safe call can produce a dangling or wrongly-protected slice; the only inherently unsafe step left to the caller is transmuting a pointer to executable memory into a function and calling it.

## Verification

Run on Windows x86_64 natively and on WSL2 (Ubuntu), Rust stable 1.95.x and the 1.85 MSRV toolchain; the same commands run in the CI matrix across Linux, macOS, and Windows:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo test --all-features
cargo build --no-default-features          # no_std build
cargo build --examples
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo bench --bench bench --all-features --no-run
cargo +1.85 build --all-features           # MSRV
cargo deny check
cargo audit
```

All green on both Linux and Windows, including the x86-64 tests that assemble and execute real machine code on each platform. Test counts at this tag:

- Default features: 16 unit + 11 integration (6 workflow + 5 property) + 14 doctests.
- `--all-features`: 16 unit + 13 integration (6 workflow + 5 property + 2 serde) + 14 doctests.
- Three runnable examples (`jit_function`, `guard_pages`, `protections`).

## What's next

The `1.0` surface is stable until `2.0`. Future work is documentation, tests, and internal optimization that does not change the public contract. The design leaves room for additive growth — for example, instruction-cache synchronization helpers for the architectures that need them (AArch64), which a caller currently performs at the point of execution — each a minor release when it lands.

## Installation

```toml
[dependencies]
pager-lang = "1"

# no_std:
pager-lang = { version = "1", default-features = false }

# with serialization of the value types:
pager-lang = { version = "1", features = ["serde"] }
```

MSRV: Rust 1.85.
